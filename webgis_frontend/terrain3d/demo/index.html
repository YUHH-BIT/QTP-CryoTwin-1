程序化建模：这次沿用了什么

  • 输出契约（学习材料 ① img2threejs 的思路）：proc.js 让灾害要素由一份 spec 生成可编辑的 THREE.Group，组内挂 userData.sculptRuntime 与 anchor_ 空物体；材质按命名约定从色板取，损毁整组切色板，锚点缺失直接抛错。目前 OSM 建筑与源区冰岩块两类资产共用这一工厂。说明：这里沿用其方法与输出契约，并未运行 img2threejs 工具本身。
  • 着色器画细节，而不是堆贴图（材料 ② 防汛白模沙盘 + ④ GPU 高度场）：buildDistanceField() 把「到 22 km 实测沟道的最短距离」烤成 768×432 距离场，地形片元着色器按距离合成常水位河面、岸线泡沫带、砾石滩、河岸植被色带与流向 V 形箭头，全由 uBankOn / uBankTime 控制，不新增几何体、不下载贴图。建筑窗格同理，用挤出几何侧面 UV 在 GLSL 里画楼层线与窗格。
  • 轮廓与可读性：屋顶 / 墙面靠 ExtrudeGeometry 自带的 cap / side 材质分组分开，另加基座薄台与 EdgesGeometry 勾边；点画布右上「口岸聚落」可飞到 OSM 建筑最密集的一簇看立面。灾害带在顶点着色器里按相机距离沿横向法向自适应加宽，片元里加流向箭头、两侧亮描边与脉冲前锋。

洪水演进实景层：按资料里的方法做，不是画示意图

点画布右上「洪水航拍」开启低角度无人机跟拍（镜头跟随水面自身的水头，不是态势层小球）。下面每一行都对应一次真实的技术选择，括号里是所沿用的案例：

镜头控制约定：在画布上拖动或滚轮缩放即立即接管视角——取消飞行插值、停止自动推演与自动旋转、退出洪水跟拍，此后相机完全由用户控制，不会再被拉回。自动运镜期间每帧按 321 格显示网格做地形安全钳制：自由视角只保证相机不钻进地面（60 单位余量），自动运镜最小离地 140 单位；跟拍机位沿沟道弧长布置（沿切线直线后退会在弯道切进侧壁，实测离地 −182 m）。默认全链条推演采用战术俯视机位：升到谷上方约 1050 m（实测俯角约 43°、离地约 645 m），看整条沟谷的走向与两侧地形关系；这里用绝对高度而不是俯角反解，后者在视距拉大时会把相机抬到 2 km 以上。「洪水航拍」仍是贴近水面的低角度近景（俯角 26°），两种观察方式并存；flyTo 终点先做地形约束。window.__cam() 可读取相机位置、接管状态、实时离地余量与 rig 解算参数。

全链条推演跟拍（默认即战术俯视）：按「播放 / 演练」或「全链条自动推演」后镜头逐帧连续跟随洪水层水头，机位即上述战术俯视，不再按 8 个阶段跳飞预设节点（那正是镜头晃动、看丢灾害的根因）；跟拍期间自动收起前锋球、圆环、灾害色带、节点标签等态势符号。锚点取画面里真有水的水头：从到达时间等值线沿沟道向上游找第一个 h/peak > 1% 的位置（相对阈值，不随视距放大系数漂移），因为等值线本身水深恰好为 0；切线用 ±300 m 基线平滑（沟道折线顶点间距中位数 63 m，±45 m 差分每个顶点跳一次方向）；锚点、机位、瞄准点分别阻尼，机位远近由湿带中心线在画面里的纵向占比有界反馈。注意口径差：水头由 arrival.bin 到达时间场反解（tField = 演示比例 × 470 s），而 KPI / 阶段里的「累计传播」来自论文时间线 frontPath(ratio)，两者在演示中段实测最大相差约 4.7 km，统一两套场的映射仍需后续处理。

局部放大逻辑：三维场景里的「中心点」是 OrbitControls 的 target。原来滚轮只让相机沿 camera → target 靠近这个固定点，加上 screenSpacePanning=false 让斜视角下几乎无法平移，所以放大不了任意部位。现在滚轮先用射线拾取光标下的地形点 P，再把相机与 target 同时相对 P 按比例缩放（C' = P + (C−P)·s，T' = P + (T−P)·s），P 在屏幕上保持不动而轨道中心逐步移到光标处；右键或 Shift+左键做屏幕空间平移，最小视距 420 → 180。

  • 宏观淹没范围由真实数据给定：用既有 arrival.bin 的到达时间（已含 6 m/s 横向漫流延迟），配合真实 DEM 相对沟床的高差做地形约束——阶地 / 河漫滩才会被淹，高陡山坡保持干燥；沟道核心保留 depth.bin 原值。论文表 4 的「平均流深」作为淹没水位包络。注意口径：既有场只给 340 m 窄带，为在实景里看见「淹没阶地 / 农田 / 道路」，这里把漫延包络按地形高差外扩到谷坡低处——这是标注清楚的视觉外推，不是二维数值解。水位放大按视距连续变化（近景约 0.5×、22 km 全景最高 3.25×），法线贴图密度同步调整；水面的横向视觉展宽约 1.6×另见下方「本页做了什么」的显式标注。KPI 数值与真实流深不变。
  • GPU 并行浅水波方程 + 子步长（④）：192×108 RGBA8 状态纹理 ping-pong，每帧 3 个子步长推进线性化浅水波方程；前锋破碎、波峰与粗糙地表持续注入波动；泡沫按流向做半拉格朗日回溯平流。干湿边界把 η 与 h 一起钳制，h 不会为负、速度不会发散。
  • 亚网格插值 → 连续曲面（④）：水面显示网格 288×162 比状态网格更密，顶点用三次 B 样条插值淹没源，得到 C2 连续曲面；时间维用带惯性的临界阻尼二阶涨水响应 + 后期退水。没有「一格一跳」的方块，也没有帧间阶跃。
  • 真实水法线贴图 + 流向扭曲 + 近景泥浆分支（②）：水面细节主来自 three.js r160 官方两张 512×512 水法线贴图，按 Valve《Portal 2》Flow 法用 half-cycle 双相位混合，并让第二层用 1.73× 不同缩放叠加打散重复；采样 uv 按真实流向场偏移，弯道处水纹顺着沟道走。程序化波纹只留 25% 作大尺度基底，配 fwidth 屏幕空间抗锯齿；噪声哈希改用无三角函数版本（大坐标下 sin 精度丢失会织出规则直角纹），相位扰动用世界坐标而非网格 uv。近景按视距切到泥浆材质：高频法线坡度衰减 78%、高光衰减 85%，改用低频悬浮泥沙斑驳表现高浓度颗粒流；远景仍是清水波光，中间连续过渡。贴图缺失时自动全量回退。浅水按法线偏移折射采样真实 Esri 影像，能透出被淹的阶地、农田与道路。
  • 水头泡沫 / 浪花 / 飞溅 / 扬尘（②⑤）：前锋由 t−T≈0 自动形成一条动态带，叠加 GPU 平流泡沫、波峰破碎与湿边薄水；1 320 个 THREE.Points 粒子只在已淹没的水头湿区生成，抛物运动、落到水面或飘到干山坡即消亡（上抛高度与寿命按近景尺度收窄）。
  • 碎冰与冰碛物真的在翻滚、碰撞、被推着走（①⑤⑥）：makeSculpt(spec) 生成可编辑 THREE.Group，480 个 InstancedMesh 实例。CPU 侧按到达时间梯度得到的流向场平流，速度用松弛而不是赋值产生惯性；浅水搁浅增摩擦、前锋湍流加大角速度；空间哈希做两两碰撞并交换角动量。块体半沉在水面下，高度按块体移动后的位置实时重采水面并做上限钳制，干区 / 出界实例直接隐藏，因此不会出现悬在半空的碎石。
  • 语义粗糙度（⑥）：由 OSM 建筑轮廓、地形坡度、距沟道距离烘焙分区阻力，驱动波浪注入、泡沫生成与湍流强度，不是全城一个系数。

本页做了什么，没做什么

  • 做了：真实 DEM 起伏 + 真实卫星影像的实景三维；等高线（每 200 m 首曲线 / 1000 m 计曲线）、22 km 沟道、灾害体沿沟推进并做「冰岩屑流 → 碎屑流 → 泥石流」相态渐变、OSM 建筑（程序化立面 / 基座 / 勾边）、岸边细节、堰塞水体与受灾范围；时间轴、图层、镜头飞行、情景滑块。
  • 没做：不求解完整二维浅水方程 / 宾汉流体阻力，不反演物源，不计算洪峰流量与流速。洪水层的 GPU 解的是线性化小振幅波方程（只负责表面波动与泡沫观感），宏观淹没范围与到达时间来自既有场数据、水位包络来自论文表 4；它不产出任何预测数字，也不替代工程水动力计算。地形约束漫延包络、垂直放大系数、波幅、碎冰数量与粒子数量均为视觉合成参数；没有倾斜摄影 / 3D Tiles 实景模型。本地沙盘建筑是 OSM 实测轮廓挤出 + 程序化立面着色（这批 OSM 数据没有 height / levels 字段，楼高按示意层高估算并做 2× 视觉放大，不代表真实楼高），Cesium 建筑为按口岸功能类型程序化重建的 glTF 示意模型。统一 ACES 色调映射 / SSAO / 全局距离雾本轮未做：自定义 ShaderMaterial 不参与 three.js 的 tone mapping 与 fog chunk，直接开会让水面与山体色调不一致；SSAO 需引入后处理链，在当前软件渲染环境下代价过高。二维数值解求解器原型已就绪但未接入页面（tools/anuga_field.py，ANUGA 4.1.0）：当前网格过粗、用一次性溃决水体代替流量过程线、四壁封闭，结果未率定，不可用于演示或工程判断。
  • 可视化约定：真实高山峡谷的谷底会被山脊完全挡住，因此灾害带、沟道线、前锋标记做成不参与深度测试的「态势叠加层」，宽度为 22 km 全景下可辨而放大，不代表真实淹没宽度。贴地要素统一采样 321 格显示网格高度。实景洪水水面相反：它参与真实深度测试，会被山体与建筑正确遮挡；22 km 全景下仅按视距放大水深的视觉高度，KPI 数值与真实流深不变。「洪水航拍」模式会自动压低态势叠加层，并隐藏堰塞湖蓝饼、受灾范围圈、节点小球与地名标签。水面网格与地形显示网格按同一条三角形对角线分片线性采样，保证两层严格共面。
  • 水面视觉口径（演示夸张，此处显式标注）：真实窄谷的湿区仅约 180 m 宽，为让它在近景跟拍里可辨，淹没势场在烘焙阶段做幂次抬升（γ = 0.60），横向视觉展宽约 1.6×；近景（视距 < 900 m）同时切到泥浆材质——高频法线坡度衰减 78%、高光衰减 85%，改用低频悬浮泥沙斑驳表现高浓度颗粒流，远景（> 2600 m）仍保留清水式波光，中间连续过渡。这两项只改观感，不改空间场、水深剖面、到达时间与 KPI；画面里的水面宽度与泥色都不代表实测淹没边界或实测流深。碎冰、飞溅粒子与刚体碰撞采样的是同一份展宽后的场，保证贴水一致。
  • 页面上所有流量、流速、流深、到达时间数字均引自论文表格或由其线性插值，不是本页模拟产生的结果；「累计传播」按 22 km 沟道弧长比例计算，「当前高程」为真实 DEM 采样。
  • 情景推演滑块改变时间轴总历时、KPI 与演进快慢，并按表 4 平均流深缩放洪水层的水位包络（因此淹没范围会随物源变化）；但到达时间场与二维水动力都不重算，这是演示级最重要的边界。
  • 正文写「8 min 20 s 到达」，表 4 写「8 min 25 s」，存在 5 s 口径差。本页统一采用表 4 的 8 min 25 s，以保证 8 组情景系列自洽。
  • 用途边界：仅用于演示、方案沟通与教学展示，不可用于防洪决策、风险评价或任何工程预测。

运行方式

本目录为独立静态页面，不依赖现有 WebGIS 系统、不依赖外网。必须把本目录作为静态服务器根目录：执行 python tools/serve.py 8765（多线程；不要用单线程的 python -m http.server，本页会并发拉取 DEM / 影像 / 库文件，单线程会把连接拒掉，表现为贴图加载失败或图表空白），浏览器打开 http://127.0.0.1:8765/（Cesium 的库、瓦片与流场帧使用 /cesium_lib/、/tiles/、/models/ 根路径，放到网站子目录需改这些路径）。Three.js r160、OrbitControls、Cesium 与全部实景数据均已本地托管，约 95 MB。

可用 ?t=300&vol=0.90 直接定位到指定时刻（秒）与物源规模（亿 m³）；加 &cine=1 直接以洪水航拍跟拍视角打开；加 &engine=cesium 直接用三维地球视图打开；?diag=1 输出运行时诊断。便于分享某一帧或截图验收。推荐组合：?t=260&cine=1&diag=1。

附带的 单图 → 程序化 Three.js 模型实验室 是独立开发页：按 img2threejs 2.0.1 的方法论，把一张参考图分 8 个 pass 重建为可编辑的 THREE.Group。它不加载本页任何 DEM / 影像 / OSM 数据，也不改动主沙盘，因此不在主界面顶栏占位。
