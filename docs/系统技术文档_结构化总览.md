# 青藏高原冰冻圈灾害数字孪生系统 · 技术设计文档

**文档版本**：v1.1（结构化整合版）　　**最后更新**：2026-09-11

---

## 文档概述

本系统面向青藏高原冰冻圈灾害（洪水、冰湖溃决、融雪、冻土热融滑塌、积雪、雪崩、风吹雪等）的数字孪生与风险评估决策，采用 **B/S 架构**，以 WebGIS 为统一时空载体。后端基于 Flask 微服务化（Blueprint）提供数据、模拟、评估、决策与系统管理能力；前端基于 OpenLayers 6.x / GeoTIFF.js / ECharts 的轻量级原生 JavaScript 体系，实现"后端计算、浏览器免插件渲染"。

文档整合项目原始设计材料，按 **前端架构 / 后端架构 / 技术路线 / 实现方法 / 关键技术 / 数据来源 / 研究方法** 七章组织，并附运维与部署要点，作为系统设计与后续开发的总纲。

**总体技术主线**：`数据 → 模拟 → 评估 → 决策 → 管理`，前端以地图为统一载体，后端以 Blueprint 按功能切分，风险评估以 `Risk = H × E × V` 为量化核心。

## 一、前端架构

### 1.1 技术栈

| 能力 | 技术选型 |
|---|---|
| 地图与多源图层叠加 | OpenLayers 6.x |
| 浏览器端 TIF 解码 | GeoTIFF.js v2.x |
| 统计图表 | ECharts |
| 工程组织 | 原生 JavaScript（无构建系统，script 标签按依赖顺序平铺加载） |

### 1.2 页面结构

系统由七个页面构成：`index`（首页综合展示）、`query`（灾害数据库）、`simulate`（过程模拟）、`alert`（风险评估）、`decision`（决策支持）、`login`（登录）、`admin`（系统管理）。

### 1.3 浏览器端 TIF 解析范式（核心）

后端只负责计算与写盘，前端负责渲染，形成"后端计算、前端免插件"的可视化闭环：

```
GeoTIFF.fromArrayBuffer(arrayBuffer)  →  写入 <canvas>  →  ol.source.ImageCanvas  →  ol.layer.Image
```

服务端因此无需任何渲染代码，所有栅格（径流、淹没、风险、气象）均走同一渲染链路。

### 1.4 图层组织与坐标系

- **图层栈**：矢量底图 + 影像底图 + 专题叠加层。
- **矢量下发**：GeoJSON 由后端经 `/data/raw/geo/*.geojson` 直发，仅放行 `.geojson` 后缀以防范路径穿越。
- **坐标系约定**：后端统一输出 **EPSG:4326**；前端经 `transformExtent(4326→3857)` 转 Web Mercator 显示；县域面栅格化在后端转 **Krasovsky_1940_Albers**。

### 1.5 主题与组件系统

- 冰蓝暗色主题，色值全部以 CSS 变量集中管理（`styles.css`）。
- 公共 UI 组件集中于 `ui-components.js`（`UI.toast / modal / alert / confirm`）。
- 按钮、统计卡等采用统一语义类（`.ui-btn-*`、`.ui-stat-card`）。

### 1.6 栅格渲染流程

通用实现 `loadGeoTiffLayer`（`simulate.js`）：

> fetch → 解码 → 取 bbox → `readRasters` → 2%/98% 分位拉伸 → `interpolateColor` 上色（20 段彩虹色带）→ `ImageCanvas` 上图。

风险分级栅格（`alert.js`）走独立路径：像元值四舍五入映射 1~5 级，查 `RISK_LEVEL_COLORS` 取色。

### 1.7 气象水文查询

复用 `loadGeoTiffLayer` 渲染能力；封装 `geotiff-render.js`（自包含渲染）与 `meteo-query.js`（温度/降水二级选择器 + 日期范围 + 结果表 + 地图加载）；在 `index` / `query` / `simulate` 三个页面同步引入以保证功能一致性。

### 1.8 前端 API 契约

| 类别 | 主要端点 |
|---|---|
| 矢量 | `/api/basin/{data,river,permafrost,glaciers,lake,weather_station,settlement,...}`、`/boundary_country\|province\|city\|county`、`/api/disaster/<type>`、`/api/disaster/types`、`/geocode` |
| 栅格 | `/backend-static/{runoff_results,flood_inundation,risk_results}/*`、`/tif/<path>`、`/api/query/{variables,list,range}` |
| 决策 | `/api/llm/chat`(SSE)、`/api/expert/profiles`、`/api/decision/content` |
| 管理 | `/api/auth/login`、`/api/auth/me`、`/api/system/status`、`/api/admin/*` |

### 1.9 前端现状与优化方向

已知待优化项：建立分层 Design Tokens（色彩/动效/字号/间距令牌）；补充 `prefers-reduced-motion` 降级；收敛三套按钮体系到 `.ui-btn`；补表单校验与焦点环；清理死代码（`es-select` / `ui-input` / `ui-skeleton` 等）。

## 三、技术路线

### 3.1 纵向主线

`数据 → 模拟 → 评估 → 决策 → 管理`。前端以 OpenLayers 地图为统一载体，后端以 Flask Blueprint 按功能切分。

### 3.2 首页（空间入口）

多源时空图层融合渲染 → 底图切换 / 流域圈选高亮 / 地理编码定位 / 图层控制 / 统计概览；作为全系统 `basin_id` 与时空参数的输入源。

### 3.3 灾害数据库（第一环）

八类冰冻圈灾害 GeoJSON + ERA5 气象水文场，经类型白名单路由与 SQLite 索引检索，提供动态计数与目录服务。

### 3.4 灾害过程模拟（计算环节）

ERA5 气温/降水 → LSTM 径流 → 分位阈值判淹没（产出 `flood_inundation`）；GLDAS 融雪 → 年极值判融雪洪水。产出是下游风险评估 **H 的强制前置**。

### 3.5 风险评估（量化核心）

`Risk = H×E×V` 栅格像元级合成，分位数相对分级 + 绝对后果阈值对照，输出四级五档分级栅格与县域真实汇总。

### 3.6 决策支持（人机中枢）

RAG 智能体（大模型代理 + 真实数据溯源）+ 院士专家名录 + 防灾决策内容库，将真实数据资产转化为可解释建议。

### 3.7 系统管理（安全基座）

RBAC 认证授权、系统状态可观测、审计日志、受控数据管理、智能体提示词配置桥接。

### 3.8 模块依赖关系

- 纵向数据流：`灾害库 → 过程模拟 → 风险评估 → 决策支持`。
- 横向基座：`首页` 与 `系统管理` 被全局依赖。

### 3.9 论文规划框架

B/S 五层架构（数据层—服务层—模型层—应用层—展示层）+ 六大功能模块；创新点定位为 **"数字孪生 + 深度学习与物理水文融合 + WebGIS 实时模拟"**。

### 3.10 已知演进方向

暴露/脆弱性网格化、多灾害统一框架（一套 H×E×V 多灾种复用）、RAG 语义化（embedding + 问即算）、三维可视化、近实时遥感接入。

## 四、实现方法

### 4.1 前端 TIF 解析与渲染实现

- **TIF 产出**：模拟请求 → `runoff_engine.simulate_runoff` → 查索引库取驱动 TIF → 裁剪 → `write_geotiff_atomic`（临时文件 + `os.replace` 原子替换 + 退避重试）写盘。
- **TIF 渲染**：`fetch(arrayBuffer)` → `GeoTIFF.fromArrayBuffer` → `getBoundingBox()` 转 3857 → `readRasters` → 2%/98% 分位拉伸 → `interpolateColor` → canvas → `ImageCanvas` → Image 图层（opacity 0.75）。
- **时序播放**：链式 `setTimeout`，每帧重新 fetch + 解码（`loopSpeedMs = 3000 / 倍速`）。

### 4.2 后端栅格写盘约束（硬性）

固定 `compress='lzw'`、`dtype=float32`、`nodata=NaN`；**禁用 zstd**（GDAL 写 tag 50000，前端 geotiff.js 仅注册 50001，曾致线上事故）。

### 4.3 风险评估实现（栅格像元级）

- **H（危险性）**：时段内 `flood_inundation` 逐像元取最大值，仅在淹没区 min-max 归一化。
- **E（暴露度）**：县域五维（GDP/人口/耕地/粮食/牲畜）就近取期 → 质心点 IDW(k=8, power=2.0) 插值 → OSM landuse 像素调制（dasymetric 思想）→ 仅在淹没区归一化 → 等权（默认）或加权合成。
- **V（脆弱性）**：SV_QTP 五期就近取期 → 面栅格化 → 缺失县用淹没区非零中位数填充 → 归一化。
- **合成**：加权几何平均 `Risk = H^wH · E^wE · V^wV`，非淹没区置 0；分位数 q20/40/60/80 分 5 级。

### 4.4 县域真实汇总（统计口径）

淹没县域**质心落入法**求和（非 IDW 面积分），避免暴露量失真；输出淹没面积 / GDP(万元) / 人口 / 耕地 / 粮食 / 牲畜及各级占比。

### 4.5 RAG 决策智能体实现

`llm.py` 作为大模型（OpenAI 兼容）安全代理，密钥仅存后端；`build_messages` 双重限流（最近 20 条、单条 ≤4000 字）；`expert_kb.build_context` 关键词路由（类型/区域/年份）→ 参数化 SQL 检索 → 注入末条用户消息并强制 `[数据源:xxx]` 标注；SSE 流式转发。

### 4.6 系统管理实现

`admin_db.init_admin_db` 幂等建表 + 种子（权限点/三角色/默认管理员）；`add_log` 非阻塞审计；`/api/admin/data-tree` 等受控文件操作（realpath 穿越防护）。

### 4.7 开发规范与可复用方法

优先复用既有能力，勿重写：`write_geotiff_atomic`、`load_json_cached`、`resolve_within`（路径防护）、`loadGeoTiffLayer` / `interpolateColor` / `createLegend`、`UI.*` 组件。

### 4.8 径流模拟实现现状

详见第五章 5.2（含已识别的致命语义缺陷与优化方案）。

## 五、关键技术

### 5.1 浏览器端 TIF 解析 + 压缩兼容红线

geotiff.js 注册解码器集合 `{1,5,7,8,32773,34887,50001}`；LZW 为踩坑后硬约束。验证脚本 `tests/test_output_frontend_readable.py` 直读 tag 259 并用前端库实跑解码回归。

### 5.2 LSTM 径流模型（关键且存在重大审查问题）

- **结构**：`RunoffLSTM` 两层 LSTM(hidden=100) + 全连接 + ReLU；输入 4 变量（气温/降水及其极大值变体），逐像元日径流；GPU/CPU 自适应批大小（GPU 上限 16384×安全系数 0.7，CPU 1024）。
- **致命缺陷（2026-08-29 审查）**：在线服务把"空间像元"当"时间步"喂给 LSTM（张量 `(1,B,4)` 而非 `(B,T,4)`），导致结果依赖 batch 大小与像元排列、跨日期无记忆、不可复现；训练/离线/在线三套序列语义互不兼容。
- **修复收益**：P0 修复（修语义 + 停填 0 + 掩膜前置 + 修融雪判据 + 删数值翻转）约 3~5 天可让模块从"不可用"变"可用且快 20~50×"。
- **实测提速**：新引擎端到端单日 21.1s（旧 159s，7.5×）；流域掩膜 0.6s（265×）；无效像元 41.6% 算力浪费已通过掩膜前置回收。

### 5.3 阈值法洪水淹没（简化水动力）

`inundation = runoff ≥ threshold ? runoff : 0`，阈值场 `grid_threshold_{10,50,90,95,99}p.tif`；可选 `basin_id` 几何掩膜；输出淹没像元数/面积/概率等统计。**代价**：忽略洪水时空滞后与汇流。

### 5.4 融雪洪水识别（年极值法）

以"当日融雪 ≥ 当年最大值"判洪水；年最大值图缓存 `GLDAS_snowmelt_max_YYYY.tif`。审查指出该判据退化为"全域几乎每天有洪水"，需改为分位/倍数 + 面积门槛。

### 5.5 H×E×V 风险评估 + 权重方法

- **框架**：乘积型 `R=H×E×V`（UNDRR / IPCC / 第一次全国自然灾害综合风险普查），栅格像元级、非淹没区置 0。
- **权重二选一**：`entropy`（默认）顶层 H/E/V 用**熵权×AHP 先验混合（凸组合，α=0.60，先验 [0.40,0.35,0.25]）** 防零化、暴露度五维用纯熵权；`custom` 由前端滑块指定。
- **熵权法要点**：比重沿"像元轴"归一化（非指标轴），否则退化为等权；退化情形回退等权防 NaN。

### 5.6 RAG 决策智能体与数据溯源

后端代理 + 密钥不出后端；强制 `[数据源:xxx]` 标注、数据未覆盖显式声明；关键词路由（非向量库）参数化 SQL 检索，降级链（类型→区域→全量）保证有上下文。

### 5.7 RBAC 认证与路径穿越防护

会话态 + 双层装饰器；`realpath + commonpath` 校验杜绝 `../` 逃逸；`/data/raw/geo/` 仅放行 `.geojson`。

### 5.8 原子写 TIF 与并发安全

`write_geotiff_atomic`（`tempfile.mkstemp` + `os.replace` + 退避重试 ≤5 次），规避 Windows 并发 `Permission denied`；`simulate.py` / `alert.py` 部分仍裸写属技术债。

### 5.9 缺失值 / 单位实测更正

ERA5 TIF 实测已是**摄氏度/毫米**（非 K/m），前端/后端均无需换算；温度含负值、0 为合法冰点，渲染透明规则按变量区分（温度 0/负不透明，降水 0 透明）。

## 六、数据来源

### 6.1 八类冰冻圈灾害 GeoJSON

类型白名单 → 文件：降雨型洪水 `PFs_HMA`、融雪型 `SFs_HMA`、冰湖溃决 `GLOFs_HMA`、滑坡堰塞湖溃决 `LLOFs_HMA`、冰川跃动 `surging_glacier_inventory`、热融滑塌 `RTS-QTP`、风吹雪、雪崩。

### 6.2 气象水文驱动（ERA5）

`data/raw/TibetanPlateau/` 下四目录——`temperature_2m/`、`temperature_2m_max/`、`total_precipitation_sum/`、`total_precipitation_max/`（每目录含 `.tif/.tfw/.tif.aux.xml`）；经 `TibetanPlateau_index.db`（variable+date→file_path）索引加速。

### 6.3 融雪数据（GLDAS）

`data/raw/GLDAS025_Snowmelt/`（50406 个扁平日文件），驱动融雪洪水识别。

### 6.4 模型与阈值

`models/lstm_runoff_model.pt`（LSTM 权重）、`thresholds/grid_threshold_{10,50,90,95,99}p.tif`（径流分位阈值）。

### 6.5 县域社会经济（暴露度 E）

GDP、人口、耕地、粮食、牲畜等县域权威统计；经 `preprocess_economy.py` 清洗（单位统一亿元→万元、别名映射 合作市→夏河县、就近取期）落盘 `*_latest.csv`。

### 6.6 脆弱性（V）

`SV_QTP_2000-2020.shp`（SV2000–SV2020 五期，0~1），按评估年就近取期栅格化；缺失县用淹没区非零中位数填充。

### 6.7 基础地理与承灾体矢量

`data/raw/geo/` 下——流域/河网、冰川/冻土/湖泊、行政区划（国省县市）、居民点/道路/铁路/气象站、水库坝/能源站点、OSM landuse。

### 6.8 DEM 与地形

`data/raw/dem/TP_China_dem.tif`（H 地形因子）；注 `config.DEM_FILE` 指向文件不存在，实际派生版在 `data/processed/dem/web_dem.tif`（待确认）。

## 七、研究方法

### 7.1 风险评估理论框架

采用国际通用 `R = H × E × V`（UNDRR / IPCC AR5 / 第一次全国自然灾害综合风险普查），物理含义清晰、三要素可独立更新。

### 7.2 栅格像元级计算原则

以像元为基本单元，逐像元三要素合成；区域约束（仅淹没区 H>0 计算）、无危险即无暴露、非淹没区 Risk=0。

### 7.3 危险性 H 合成

时段 `[t_s,t_e]` 内逐日 `flood_inundation` 取最大值 `H_raw=max(D_t)`，淹没区 min-max 归一化；H 综合了气象+融雪 → LSTM 径流 → 阈值判淹没的完整致灾链。

### 7.4 暴露度 E 空间化

县域权威统计就近取期 → 质心点 IDW(k=8, power=2.0) 插值 → OSM landuse 像素调制（dasymetric 思想，向真实承灾地类集中）→ 五维等权（默认）或加权合成；缺县域面图层时为真 dasymetric 的稳健替代（`_dasymetric_distribute` 接口已预留）。

### 7.5 脆弱性 V 与缺失处理

SV_QTP 五期就近取期栅格化；缺失县用研究区非零 SV 中位数填充（避免脆弱性异常归零）；归一化；不可用时回退常数 0.5。

### 7.6 风险分级方法

分位数分级（q20/40/60/80 → 5 级，各级面积均衡）用于"相对区划"；叠加"淹没 GDP>X 万元 / 淹没人口>Y 人"绝对后果阈值对照用于"决策量级"。**注**：绝对后果阈值对照在 `alert.py` 中规划但未完全落地（现状仅相对分位数法）。

### 7.7 权重客观赋权方法

熵权法（信息熵越小权重越大，沿像元轴归一化）；顶层 H/E/V 用熵权×AHP 先验凸组合（防结构性因子被数据判 0，α=0.60）；暴露度五维纯熵权；支持前端自定义。实证对比显示混合后权重稳定、物理合理、无零权。

### 7.8 县域真实汇总方法

质心落入法（淹没县域质心落入淹没区者求和），与 IDW 插值面积分解耦，使统计口径与"县域权威统计"一致、可溯源。

### 7.9 社会经济数据预处理流程

单位统一（亿元→万元）→ 宽表逆透视成长表 → 字段重命名 → 缺失值（就近取期/中位数/邻域插值）→ 格式统一 UTF-8 CSV 长表 → CRS 统一（Krasovsky_1940_Albers）→ 县域名称映射 → 栅格化/IDW。

### 7.10 模型验证方法（规划 / 缺口）

文档要求 LSTM 径流 NSE≥0.85，但代码中无评估指标；需补 train/val/test 划分（按水文年）、NSE/KGE/PBIAS/FHV/FLV 与历史灾情点 ROC 校验；引入 warm-up 期与滑窗状态传递。

### 7.11 径流模拟优化审查方法论

静态代码走查 + 权重/栅格元数据实测；区分"致命/高/中/低"严重度；以"先修语义再谈提速"为原则，给出 P0~P3 优先级与验收指标（batch_size 不变性 RMSE<1e-6 等）。

### 7.12 可复现与溯源规范

知识库构建幂等（`build_kb`）、管理库种子幂等、阈值/模拟产物可重跑；LLM 强制 `[数据源:xxx]` 标注、所有结论可溯源至内部或公开权威数据，杜绝编造。
