> 文档集性质：面向科研评审的模块级技术思路合集

## 1 系统总体架构

系统以"**数据—模拟—评估—决策—管理**"为纵向主线，前端以 OpenLayers 地图为统一载体，后端以 Flask Blueprint 按功能切分为独立模块，共享 `BASE_DIR` 配置与 SQLite 索引（`TibetanPlateau_index.db`、`era5_index.db`、`admin.db`、`expert_kb.db`）。

```
┌──────────────────────────── 前端（OpenLayers + ECharts） ────────────────────────────┐
│ 首页(index) │ 灾害数据库(query) │ 过程模拟(simulate) │ 风险评估(alert) │ 决策支持(decision)│ 系统管理(admin) │ 登录(login) │
└───────┬──────────────┬──────────────────┬───────────────┬──────────────┬──────────────┬─────────┘
        │              │                  │               │              │              │
┌───────▼──────────────▼──────────────────▼───────────────▼──────────────▼──────────────▼─────────┐
│                              后端（Flask Blueprint，统一 BASE_DIR）                                │
│  basin/geocode/data_query │ disaster │ simulate/snowmelt_flood │ alert │ llm/expert/decision       │
│  （空间与查询基座）        │（8类灾害）│（LSTM径流·阈值淹没·融雪） │(H×E×V)│（RAG智能体·专家·内容）  │
│                           │          │                         │        │                        │
│  auth（认证）── system（状态）── admin（用户/角色/权限/日志/数据/智能体配置）── admin_db（SQLite）   │
└───────┬──────────────────┬─────────────────────────────────────────────────────────────────────┘
        │                  │
┌───────▼──────────────────▼──────────────── 数据与模型资产（data/） ───────────────────────────┐
│ GeoJSON 灾害库 / ERA5·GLDAS 气象 / LSTM 模型 / 阈值场 / SV_QTP 脆弱性 / 县域五维经济 / OSM landuse │
└───────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 3 模块依赖关系

### 3.1 纵向数据流（核心主线）

```
灾害数据库(02) ──► 过程模拟(03) ──► 风险评估(04) ──► 决策支持(05)
     │                │  flood_inundation      │ 风险分级      │ 引用真实数据作答
     │                │  (H 的强制前置)        │              │
     └──── 真实数据底座（GeoJSON/ERA5/县域经济）──────────────┘
```

- **(02)→(03)**：模拟模块读取灾害库/ERA5 索引与 LSTM 模型，生成逐日 `flood_inundation` 栅格。
- **(03)→(04)**：`flood_inundation` 是风险评估 **H（危险性）的强制前置**；缺数据时评估接口返回 `NO_INUNDATION_DATA` 并区分三种缺失情形引导上游。
- **(04)→(05)**：风险分级与"高风险区识别"作为智能体与方法学（`kb_methods`）的引用依据；内容库（工程/非工程措施）与之联动。
- **(02)(03)(04)→(05)**：决策支持 RAG 知识库（`expert_kb.db`）直接由灾害库、ERA5 索引、县域经济构建，使智能体回答可溯源至上述模块真实产出。

### 3.2 横向基座（被全局依赖）

- **首页(01)**：空间与查询基座（`basin`/`geocode`/`data_query`），为所有业务页提供地图渲染、流域高亮、地名定位与共用的 WMTS/GeoJSON 加载能力。
- **系统管理(06)**：安全与运维基座。`auth.login_required` + `admin.permission_required` 是受保护接口的统一防线；`system.status` 提供真实运行状态；`admin` 数据管理面向 `data/` 全树提供受控文件运维；`agent-config` 桥接决策智能体提示词。

### 3.3 关键接口契约

| 生产者 | 接口/产物 | 消费者 |
|--------|-----------|--------|
| `simulate.py` | 逐日 `flood_inundation` 栅格 + `/flood-inundation` | `alert.py`（H）、`expert_kb`（ERA5 现状）、`system.status`（计数） |
| `alert.py` | 四级 5 级分级 GeoTIFF + 县域真实汇总 JSON | 首页叠加展示、`expert_kb`（方法学） |
| `disaster.py` | `/api/disaster/<type>`（动态计数） | 首页图层、决策 RAG 语料 |
| `expert_kb.py` | `build_context(question)` → 上下文+引用 | `llm.py`（`/api/llm/chat`） |
| `auth.py` | `login_required` / `/me` | 全站前端路由守卫、admin 写接口 |
| `admin.py` | `permission_required(code)` / `agent-config` | `llm.py` 提示词管理、各写操作鉴权 |
| `system.py` | `/api/system/status` | 系统管理页状态面板 |

## 4 统一技术约定

- **坐标系与分辨率**：所有栅格统一 CRS 与像元分辨率（与 `flood_inundation` 一致），县域汇总以质心匹配。
- **认证与授权**：会话态（Cookie + `SECRET_KEY`），RBAC 14 权限点 / 3 内置角色；401/403 语义分流。
- **数据真实性与溯源**：灾害/经济/专家/决策内容均来自系统内部或公开权威数据并保留 `source`；LLM 强制 `[数据源:xxx]` 标注，杜绝编造。
- **幂等与可重跑**：知识库构建、管理库种子、阈值/模拟产出均设计为可重复执行。
- **安全**：LLM 密钥不出后端；文件操作路径穿越防护；审计日志非阻塞写入。

## 5 已知共性边界与演进方向

1. **暴露/脆弱性网格化短板**：E/V 仍县域级+空间插值，缺 WorldPop、网格 GDP/夜间灯光、土地覆盖公共产品（见《数据需求与缺口对照》P0）。
2. **多灾害统一框架**：雪/冰/冻土风险评估复用 `H×E×V`，按各自 H 来源扩展，实现"一套框架、多灾种复用"。
3. **RAG 语义化**：当前关键词路由，后续可接 embedding 向量库与在线计算结果注入（"问即算"）。
4. **管理增强**：会话即时吊销、权限点可视化注册、数据版本/回收站、日志归档。
5. **模型验证**：缺历史灾情点做 ROC/命中率校验，规划整理历史山洪与 GLOF 事件点用于分级验证。
